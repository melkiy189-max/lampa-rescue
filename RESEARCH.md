# Lampa Rescue — исследование плагинов перед разработкой агрегатора

Дата исследования: 2026-10-25.

Цель: создать одно расширение Lampa для LG 42LF630V / webOS, которое после открытия карточки фильма собирает результаты нескольких онлайн-источников в одном списке. Пользователь сам выбирает сервис, озвучку, эпизод и может вернуться к списку и переключиться.

## Важная оговорка о «топ-10»

Достоверной публичной статистики установок/просмотров всех плагинов не найдено. Поэтому это не рейтинг по числу пользователей, а выборка заметных онлайн-плагинов и архитектурных примеров, которые повторяются в каталогах и открытых репозиториях.

## Первичный разбор десяти решений

### 1. Онлайн Мод
Исходник-снимок: https://github.com/bthos/docs-lampa-plugins/blob/main/analysis/raw/nb557.github.io_plugins_online_mod.js
Размер исследованного файла — около 552 КБ. Есть много отдельных поисковых адаптеров, общая работа с Lampa.Reguest, Storage и Player; поиск по множеству сервисов и выбор плейлиста. Код сильно обфусцирован, много прокси/зеркал и скрытых зависимостей. Вывод: подтверждает реализуемость общего списка источников, но копировать целиком не стоит.

### 2. BWA RC
Исходник-снимок: https://github.com/bthos/docs-lampa-plugins/blob/main/analysis/raw/bwa.to_rc
Размер — около 79 КБ. Компонент Lampa с фильтрами, выбором балансера, сохранением выбора, поиском, сезонами/озвучками и запуском через Lampa.Player. Зависит от SignalR/WebSocket и удалённого RCH-сервера; часть адресов работает по HTTP. Полезны UX-паттерны, но зависимость от сервера — отдельный риск.

### 3. BWA Cloud
Каталог и найденные обёртки: https://github.com/lampa-kit/lampa-kit.github.io/blob/main/list.js
В доступном зеркале встречается загрузчик, подключающий удалённый cloud.js; это не полный исходный код облачного сервиса. Наличие wrapper-файла не означает, что код поиска открыт. Для собственного адаптера нужен фактический код или документированный API.

### 4. Showy
Исходник-снимок: https://github.com/bthos/docs-lampa-plugins/blob/main/analysis/raw/showy.online_m.js
Размер — около 98 КБ. Есть собственный экран результатов, поиск, запуск плеера и выбор вариантов. Зависимости: showwwy.com, RCH/SignalR, токен устройства в Storage; часть сетевых адресов — HTTP. Это не автономный локальный скрипт: отдельно нужны протокол и авторизация.

### 5. Filmix как отдельный источник
Исходник: https://github.com/yumata/lampa-source/blob/main/plugins/online/filmix.js
Размер — около 17 КБ. Отдельный адаптер выполняет поиск, получает варианты/качество и передаёт выбранный поток в Lampa.Player; использует Lampa.Reguest. Зависит от Filmix API (в исследованной версии filmixapp.cyou/api/v2/), идентификатора устройства и авторизационных данных. Хороший пример структуры provider-адаптера; адреса API и авторизацию нужно проверять при реализации.

### 6. Онлайн Stream (arkmv.ru/vod)
Исходник-снимок: https://github.com/bthos/docs-lampa-plugins/blob/main/analysis/raw/arkmv.ru_vod
Размер — около 74 КБ. Общий экран со списком балансеров, фильтрами, сохранением выбора, поиском, эпизодами и передачей ссылок плееру. Зависит от удалённого Lampac-подобного API и SignalR/RCH для удалённых запросов. По интерфейсу близок к желаемому, но его нельзя просто переименовать в свой плагин: существенная логика живёт на сервере.

### 7. Онлайн Cinema
Исходник-снимок: https://github.com/bthos/docs-lampa-plugins/blob/main/analysis/raw/bylampa.github.io_cinema.js
В исследованной копии это обфусцированный загрузчик, подгружающий дополнительный код с IP-адреса по HTTP. В качестве основы не подходит без восстановления и проверки логики; удалённый динамический код не соответствует требованию прозрачности.

### 8. Z1 Online
Найденный GitHub-wrapper: https://github.com/cevamnelampaplagin/tytnemanichogodobrogo/blob/main/z1online.js
Это короткий загрузчик, подключающий online.js и lampac-src-filter.js с z01.online; сам поиск и работа с источниками в wrapper не реализованы. Наличие файла на GitHub не означает, что исходники сервиса открыты.

### 9. MODS
Исходник-снимок: https://github.com/bthos/docs-lampa-plugins/blob/main/analysis/raw/lampa.stream_modss
В исследованном файле есть удалённая загрузка JavaScript с последующим eval(). Поведение может измениться на сервере без изменения файла в нашем репозитории, поэтому напрямую встраивать его в основу не следует.

### 10. HDRezka — отдельная реализация с понятной структурой
Исходник: https://github.com/D1N0v/hdplugin/blob/main/hdrezka.js
Размер — около 37 КБ. ES5-код, отдельный экран, поиск, выбор озвучки/эпизода и запуск через Lampa.Player. Ограничение: проект явно предусматривает companion server; GitHub Pages раздаёт только клиентский JS. Одного статического файла недостаточно для полноценного источника.

## Общие закономерности

1. Повторяются Lampa.Component, Lampa.Listener, Lampa.Activity, Lampa.Reguest, Lampa.Storage, Lampa.Player.play() и Lampa.Player.playlist().
2. Интерфейс Lampa — только клиент. Поиск и получение ссылок часто выполняются удалённым API/сервером или RCH/SignalR-мостом.
3. Результаты неоднородны: один источник возвращает озвучки и серии, другой — готовые ссылки, третий — только перенаправление на внешний сервис.
4. Переключение возможно, но общий экран должен хранить нормализованные результаты и передавать выбор специфичному адаптеру, а не считать все URL одинаковыми.
5. Для старого webOS стоит начинать с ES5-совместимого кода и штатных Lampa API; проверять HLS/MP4 на реальном телевизоре.
6. Не использовать непрозрачные загрузчики, eval() и произвольные HTTP-прокси. Не пересылать учётные данные неизвестным сторонним сервисам.
7. Лицензии многих найденных снимков не указаны. Их можно изучать как архитектурные примеры, но нельзя автоматически считать разрешённым копирование кода.

## Рекомендуемая архитектура Lampa Rescue

- Core: единый экран результатов, поиск, таймауты, дедупликация, сортировка, ошибки и возврат к списку.
- Providers: независимый адаптер каждого источника с методами поиска и нормализации результата.
- Нормализованный результат: provider, title, year, season, episode, voice, quality, streamUrl или playAction, subtitles, metadata.
- playAction позволяет адаптеру продолжать собственную логику, если сервис не отдаёт прямую ссылку.
- Settings: включение/отключение источников, таймауты, порядок отображения и диагностика.
- webOS: только проверенные возможности старого WebView; без обязательной зависимости от Node.js на телевизоре.

## Ключевой технический выбор

Если все провайдеры требуют собственных удалённых API, CORS-прокси или RCH-сервера, полностью автономный плагин на GitHub Pages не сможет заменить их без этих зависимостей. Есть два пути:
- Клиентский агрегатор: подключает источники, чьи API доступны непосредственно из Lampa.
- Собственный backend: принимает запросы от одного Lampa-плагина, выполняет адаптеры на сервере и возвращает единый список результатов.

Для первого прототипа надо проверить, какие источники реально работают с LG webOS и какие можно подключить без небезопасных внешних мостов. Сервис появляется в списке только после успешного ответа — никаких фальшивых результатов.
