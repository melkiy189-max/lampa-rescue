# Lampa Rescue — план тестирования

Документ разделяет автоматические проверки кода и проверки, которые требуют настоящей Lampa / телевизора. Успешная проверка синтаксиса **не** означает, что источник найдёт фильм или что видео воспроизведётся.

## 1. Автоматические проверки

Запускаются GitHub Actions workflow `.github/workflows/checks.yml` при push в `main`, pull request и вручную.

- [ ] `node --check` для основных JS-файлов и обоих тестовых скриптов.
- [ ] `tests/check-source.js` проверяет критические статические защиты и точное совпадение объединённой сборки с исходниками.
- [ ] `tests/runtime.test.js` запускает ядро в Node.js с минимальными заглушками Lampa/jQuery и проверяет регистрацию провайдера, владение поиском, повторный callback, изоляцию устаревшего ответа и отбрасывание `javascript:`, `file:` и пустого URL.
- [ ] В ядре и объединённой сборке присутствует API регистрации провайдера.
- [ ] URL результата проверяется перед передачей плееру.
- [ ] Обработчик выбора использует снимок результатов текущего отображения.
- [ ] Filmix-адаптер отказывается от HTTP-прокси.
- [ ] Нормализация названий учитывает `ё/е`.
- [ ] Объединённая сборка содержит актуальные версии ядра и Filmix-адаптера.

## 2. Дополнительные сценарии ядра

Автоматический runtime-тест сейчас покрывает только базовый жизненный цикл с одним mock-провайдером. Остальные сценарии ниже пока остаются в плане и не должны считаться пройденными. Тестовые результаты не подключаются к реальному интерфейсу.

- [ ] Нет провайдеров: показать понятное пустое состояние, без фиктивных источников.
- [ ] Провайдер вернул 2 результата: показать оба и передать выбранный правильный URL.
- [ ] Один провайдер завершился ошибкой: остальные результаты остаются доступными.
- [ ] Провайдер завис: поиск завершается по тайм-ауту.
- [ ] Провайдер вызвал callback дважды: второй ответ игнорируется.
- [ ] Быстро открыть другой фильм: старый ответ не изменяет новый список.
- [ ] Уничтожить экран во время поиска: поздний callback не должен запускать старый результат.
- [x] Некорректный URL (`javascript:`, `file:`, пустая строка) отбрасывается в runtime-тесте до передачи плееру.
- [ ] Ошибка запуска плеера не ломает интерфейс; пользователь получает сообщение.
- [ ] Повторная загрузка скрипта не создаёт второй экземпляр кнопки/компонента.

## 3. Проверки Filmix-адаптера

Проводить только с разрешённым аккаунтом и доверенным HTTPS-прокси. Не публиковать токен, URL с параметрами авторизации и сетевые логи с секретами.

- [ ] Нет настроенного прокси: понятная ошибка, сетевой запрос не отправляется.
- [ ] HTTP-прокси: отклоняется до передачи токена.
- [ ] Ошибка API, неверный JSON или пустой ответ: корректное завершение без ложного результата.
- [ ] Название с `ё/е`, год и неоднозначные совпадения: неподходящая карточка не выбирается автоматически.
- [ ] Ответ с неизвестной структурой `player_links`: нет аварийного завершения.
- [ ] Поток с заявленным качеством: проверить, что построенный URL действительно существует; сейчас преобразование ссылки по шаблону не подтверждено.
- [ ] Проверить 480p/720p/1080p на устройстве; не считать максимальное качество самым совместимым.
- [ ] Сериал: до реализации поддержки серий адаптер не должен выдавать фильм как серию.

## 4. Ручной прогон на LG 42LF630V / старом webOS

Проводить на тестовой копии Lampa, сохранив возможность вернуться к штатной версии.

- [ ] Скрипт загружается без ошибок в консоли.
- [ ] Кнопка Rescue появляется один раз в карточке фильма.
- [ ] Переход к списку и возврат назад работают пультом.
- [ ] Фокус пульта виден; длинные названия не ломают список.
- [ ] Пустое состояние, загрузка, частичный ответ, ошибка и тайм-аут отображаются правильно.
- [ ] Выбор источника запускает правильный поток.
- [ ] После ошибки можно вернуться к списку и выбрать другой источник.
- [ ] Повторный запуск другого фильма не использует старые результаты.
- [ ] Проверить несколько запусков подряд, переходы в спящий режим и возврат в приложение.
- [ ] Проверить реальные кодеки/контейнеры, звук, перемотку, остановку и возврат из плеера.

## 5. Критерии готовности

Сборку нельзя называть стабильной, пока не выполнены все условия:

1. Автоматические проверки проходят на текущем коммите.
2. Есть хотя бы один источник с подтверждённым API-контрактом и воспроизводимым результатом.
3. На целевом телевизоре подтверждены поиск, выбор, воспроизведение и восстановление после ошибки.
4. Неиспытанные источники помечены экспериментальными и не выдаются за работающие.
5. У пользователя есть короткая инструкция установки, отката и сбора безопасного диагностического отчёта.

## Текущий статус

- Статические и базовые runtime-тесты подключены к CI; результат GitHub Actions для каждого коммита нужно проверять отдельно.
- Filmix остаётся экспериментальным: API, прокси и поток на целевом телевизоре ещё не подтверждены.
- Реальный прогон на LG не выполнен из среды разработки.
