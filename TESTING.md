# Lampa Rescue — план тестирования

Документ разделяет автоматические проверки кода и проверки, которые требуют настоящей Lampa / телевизора. Успешная проверка синтаксиса **не** означает, что источник найдёт фильм или что видео воспроизведётся.

## 1. Автоматические проверки

Запускаются GitHub Actions workflow `.github/workflows/checks.yml` при push в `main`, pull request и вручную.

- `node --check` проверяет синтаксис основных JS-файлов и тестов.
- `tests/check-source.js` проверяет критические статические защиты и совпадение экспериментальной сборки с исходниками.
- `tests/runtime.test.js` запускает ядро с заглушками Lampa/jQuery и проверяет жизненный цикл поиска, быстрые переключения фильмов, поздние ответы, ошибки и тайм-ауты провайдеров.
- `tests/diagnostic-init.test.js` проверяет отложенную инициализацию диагностического плагина.
- `tests/host-test.test.js` проверяет статические условия тестового экрана RUTUBE/VK.
- Все автоматические проверки — не доказательство работы реального сайта или телевизора.

## 2. Изолированный тест RUTUBE / VK Видео

Файл: `lampa-rescue-host-test.js`

Raw URL для добавления в плагины Lampa:
`https://raw.githubusercontent.com/melkiy189-max/lampa-rescue/main/lampa-rescue-host-test.js`

Этот модуль отдельный: он не подключает ядро Rescue, Filmix или поиск по названию и не меняет настройки других источников.

### Порядок проверки на LG 42LF630V

1. Сначала сохрани себе этот адрес, чтобы не искать его повторно.
2. В Lampa открой настройки и раздел плагинов. Добавь **только** URL выше как отдельный плагин. Названия пунктов меню могут отличаться в конкретной сборке Lampa.
3. Вернись в каталог, открой карточку любого фильма. Должна появиться кнопка «Тест RUTUBE / VK».
4. Открой тест. В поле ссылки вставь адрес публичного ролика RUTUBE, например обычную ссылку на страницу ролика. Тест сам преобразует её в адрес embed-плеера.
5. Выбери «Открыть встроенный плеер». Подожди до 20–30 секунд. Отметь, появился ли интерфейс плеера, началось ли видео, есть ли звук и можно ли остановить/вернуться назад.
6. Если RUTUBE проверен, отдельно проверь VK. Для текущего прототипа нужна ссылка встраивания `video_ext.php` с параметрами `oid`, `id` и `hash`. Обычная ссылка на VK-видео пока не преобразуется автоматически.
7. После теста удали только плагин с адресом `lampa-rescue-host-test.js` из списка плагинов и перезапусти Lampa, если нужно. Не удаляй другие плагины и не заменяй основной URL Lampa Rescue.

### Что сообщить по результату

Для каждого сервиса напиши:
- «кнопка есть / кнопки нет»;
- «экран открылся / не открылся»;
- «плеер появился / чёрный экран / ошибка»;
- «видео и звук есть / видео без звука / ничего не играет»;
- если была ошибка — точный текст или фотографию экрана.

**Важно:** не вводи пароль, токен или другие личные данные. Тест принимает только ссылки на публичные ролики. Успешное открытие iframe ещё не гарантирует, что поиск фильмов по названию будет доступен.

## 3. Дополнительные сценарии ядра

- [x] Нет включённых провайдеров: показывается понятное сообщение.
- [x] Быстро открыть несколько фильмов подряд: старые ответы не изменяют новый список.
- [x] Поздние ответы от уничтоженных экранов игнорируются.
- [x] Небезопасные URL `javascript:`, `file:` и пустые URL отбрасываются.
- [x] Выбор результата передаёт плееру правильный URL; ошибка запуска вызывает уведомление.
- [x] Повторная загрузка ядра не должна дублировать компонент/обработчики.
- [x] Ошибка одного источника не стирает успешные результаты другого.
- [x] Зависший источник не должен бесконечно блокировать результаты уже ответивших провайдеров.

Эти пункты проверяются с тестовыми заглушками, не с реальными фильмами.

## 4. Проверки Filmix-адаптера

Проводить только с разрешённым аккаунтом и доверенным HTTPS-прокси. Не публиковать токен, URL с параметрами авторизации и сетевые логи с секретами.

- [ ] Нет настроенного прокси: понятная ошибка, сетевой запрос не отправляется.
- [ ] HTTP-прокси: отклоняется до передачи токена.
- [ ] Ошибка API, неверный JSON или пустой ответ: корректное завершение без ложного результата.
- [ ] Название с `ё/е`, год и неоднозначные совпадения: неподходящая карточка не выбирается автоматически.
- [ ] Ответ с неизвестной структурой `player_links`: нет аварийного завершения.
- [ ] Поток с заявленным качеством: проверить, что построенный URL действительно существует.
- [ ] Проверить 480p/720p/1080p на устройстве.
- [ ] Сериал: до реализации поддержки серий адаптер не должен выдавать фильм как серию.

## 5. Критерии готовности

Сборку нельзя называть стабильной, пока не выполнены все условия:

1. Автоматические проверки проходят на текущем коммите.
2. Есть хотя бы один источник с подтверждённым API-контрактом и воспроизводимым результатом.
3. На целевом телевизоре подтверждены поиск, выбор, воспроизведение и восстановление после ошибки.
4. Неиспытанные источники помечены экспериментальными и не выдаются за работающие.
5. У пользователя есть короткая инструкция установки, отката и сбора безопасного диагностического отчёта.

## Текущий статус

- Автоматические проверки подключены к CI.
- Изолированный тест RUTUBE/VK готов для ручного прогона; реальные плееры на LG ещё не проверены.
- Filmix остаётся экспериментальным: API, прокси и поток на целевом телевизоре не подтверждены.
- Реальный прогон на LG не выполнен из среды разработки.
