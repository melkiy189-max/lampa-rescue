# План интеграции серверных источников

Статус: исследование завершено на уровне архитектуры; реализация и воспроизведение пока не проверены на LG 42LF630V.

## Почему нельзя просто скопировать адаптер LordFilm в браузер

Публичный модуль [LordFilm в Lampac NextGen](https://github.com/lampac-nextgen/lampac/tree/main/Modules/OnlineRUS/LordFilm) показывает полный путь получения потока: поиск по странице сайта, обход JS-челленджа с cookie-сессией, извлечение embed-плеера, разбор HLS/DASH и проксирование вложенных ссылок. Это серверная работа, не один URL, доступный из старого WebView.

Ключевые сведения из документации Lampac:
- клиентский плагин — `/online.js`;
- единый агрегатор источников — `/lite/events`;
- отдельный источник — `/lite/{provider}`, в том числе `/lite/lordfilm`;
- для LordFilm HLS указан как более совместимый режим; DASH может отдавать AV1 и не подходит многим старым телевизорам;
- модуль принудительно проксирует сегменты CDN, поскольку ссылки могут быть привязаны к IP.

Источник: [Lampac NextGen README](https://github.com/lampac-nextgen/lampac), [Online module README](https://github.com/lampac-nextgen/lampac/blob/main/Online/README.md), [LordFilm module](https://github.com/lampac-nextgen/lampac/tree/main/Modules/OnlineRUS/LordFilm).

## Решение для Lampa Rescue

Не делать Lampac обязательной зависимостью и не писать собственный парсер LordFilm, пока не подтверждены совместимость и поток. Сначала исследовать минимальную интеграцию с уже существующим совместимым backend, сохранив наше ядро ответственным за единый интерфейс и пользовательский опыт.

Предварительный порядок:
1. Проверить формат ответа `/lite/lordfilm` и способы вызова с клиента; не считать формат установленным только по названию маршрута.
2. Определить, можно ли подключаться к backend с адресом, который пользователь контролирует. Не зашивать чужой публичный сервер и не передавать ему токены без явного согласия.
3. Проверить доступность HLS в старом WebView и реальное воспроизведение на телевизоре.
4. Только после успешного теста добавить адаптер, таймауты, понятные ошибки и диагностику.
5. Затем испытать Filmix по тому же чек-листу: поиск, точное совпадение фильма и года, получение потока, озвучка, запуск, отмена запроса и таймаут.

## Критерии качества источника

Источник считается рабочим только после подтверждения всех обязательных пунктов:
- запрос завершается и корректно обрабатывает отказ/таймаут;
- результат относится к нужному фильму/сериалу, а не только похож по названию;
- ссылка действительно ведёт к потоку или к документированному обработчику воспроизведения;
- старый WebView умеет открыть выбранный формат;
- отказ источника не ломает другие результаты;
- не используется неизвестный публичный CORS-прокси по умолчанию.

До прохождения этих проверок источник остаётся экспериментальным и не должен называться готовым.
