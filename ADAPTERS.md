# Lampa Rescue — контракт адаптеров

Этот документ нужен, чтобы подключать источники независимо и не ломать общий интерфейс.

## Контракт ядра

Ядро предоставляет:

- `window.LampaRescue.registerProvider(provider)`
- `window.LampaRescue.getProviders()`
- `window.LampaRescue.getResults()`

Минимальный адаптер:

```javascript
(function () {
    'use strict';

    function init() {
        if (!window.LampaRescue) return;

        window.LampaRescue.registerProvider({
            id: 'example-provider',
            name: 'Example Provider',
            enabled: true,

            search: function (movie, done) {
                // 1. Запросить реальный API/страницу источника.
                // 2. Проверить ответ и извлечь только реальные варианты.
                // 3. Передать done(null, results).
                // При ошибке: done(error, []).
                // Формат результата:
                // {
                //   title: 'Название',
                //   url: 'https://...',
                //   quality: '1080p',
                //   voice: 'Озвучка'
                // }
                done(null, []);
            }
        });
    }

    if (window.appready) init();
    else if (window.Lampa && Lampa.Listener) {
        Lampa.Listener.follow('app', function (event) {
            if (event && event.type === 'ready') init();
        });
    }
})();
```

Пример выше — только контракт для разработчиков, не подключённый источник. Пустой массив означает «нет результатов» и не должен показываться пользователю как найденный вариант.

## Обязательные проверки перед включением адаптера

1. Источник реально доступен из старого webOS WebView.
2. HTTPS, CORS и формат ответа проверены на целевом устройстве.
3. Понятно, нужны ли токены/авторизация, и где они хранятся.
4. Поиск фильма и сериала работает отдельно; сезоны и серии не смешиваются.
5. Качество, озвучка и субтитры соответствуют данным источника.
6. Ссылка действительно запускается через плеер Lampa либо используется специализированный `play`-обработчик.
7. Тайм-аут, отмена поиска и сетевые ошибки не ломают другие адаптеры.
8. Есть законное основание на использование API/кода; чужой исходный код не копируется без проверки лицензии.

## Первый адаптер: Filmix (экспериментальный)

Файл `lampa-rescue-filmix.js` создан на основе публично наблюдаемого контракта Filmix-плагина: поиск по `story`, карточка по ID, затем `player_links.movie`. Он использует сохранённые в Lampa параметры `fxapi_token`, `fxapi_uid` и `fxapi_proxy`, если они уже есть. Пароль не запрашивается; токен не сохраняется в коде. По умолчанию прокси не задан: его нужно настроить отдельно. Важно: прокси технически видит параметры запроса, включая токен, поэтому нельзя использовать неизвестный публичный прокси.

**Ограничения:** адаптер пока поддерживает только фильмы, а не сезоны/серии. API использует адрес `http://filmixapp.vip/api/v2/`, найденный в публичном Lampa-адаптере; сторонняя документация также указывает на меняющиеся API-хосты. Адрес доступен только через настроенный прокси в текущей схеме. Фактическая доступность, политика прокси, CORS и воспроизведение на LG webOS ещё не проверены. Ссылки выдаются только при наличии формата качества и HTTP(S)-URL. Совпадение карточки сверяется по названию/году, но требует тестирования на реальных примерах. Не считать адаптер готовым к повседневному использованию до проверки на ТВ.


## Следующий кандидат: Lordfilm

Lordfilm добавлен в список желаемых источников по просьбе пользователя. Пока это только кандидат на исследование, а не рабочий адаптер: не подтверждены стабильный адрес сайта, структура поиска, доступ к видеоссылкам и совместимость с WebView старого LG webOS.

Перед реализацией нужно проверить:

1. Какой домен Lordfilm действительно доступен из сети пользователя и не является зеркалом-подменой.
2. Можно ли получить результаты поиска без авторизации и без выполнения небезопасного стороннего кода.
3. Как сайт отдаёт варианты качества/озвучки и прямые ссылки; не выдавать страницу фильма за прямой поток.
4. Нужен ли прокси для CORS и какие данные через него проходят.
5. Можно ли воспроизвести хотя бы один законно доступный тестовый поток на старом webOS WebView.

Реализацию не следует начинать с выдуманного API или жёстко зашитого случайного зеркала. Если выяснится, что сайт постоянно меняет домены или требует небезопасного прокси, адаптер должен сообщать понятную ошибку и не возвращать фиктивные результаты.

## Ограничения текущего ядра

- Ядро пока не содержит встроенных производственных адаптеров.
- Не считать прямую URL-ссылку универсальным форматом: некоторым источникам нужен собственный `play`-обработчик или плейлист.
- Интерфейс и жизненный цикл компонента должны быть проверены на телевизоре перед выпуском.
- До завершения проверок файл `lampa-rescue-core.js` — тестовый прототип, а не замена действующей установочной версии.


### Проверка по открытой реализации Lampac NextGen (2026-10-25)

Нашлась конкретная реализация LordFilm в публичном репозитории [lampac-nextgen/lampac](https://github.com/lampac-nextgen/lampac/tree/main/Modules/OnlineRUS/LordFilm). Это уточняет картину, но не означает, что готовый адаптер можно безопасно перенести в клиентский JS.

Подтверждённые детали из README и кода модуля:

- В качестве текущего примера хоста указан https://gv.lordfilm5.pro; домен может меняться, поэтому не считаем его вечным или гарантированно доступным.
- Поиск выполняется POST-запросом на /search-result/ с полями do=search, subaction=search, story=<название>; отдельного Kinopoisk API у сайта модуль не использует.
- На странице извлекается ID плеера api.nextembed.ws/embed/...; разбор поддерживает фильмы и сериалы.
- Модуль описывает HLS и DASH, сезоны/серии, аудиодорожки и субтитры. Для совместимости по умолчанию выбран HLS; DASH/AV1 не следует считать подходящим для старого LG.
- Сайт использует JS-челлендж и cookie-сессию. Реализация Lampac держит сессию на сервере и проксирует манифесты/сегменты; для CDN указано ограничение домена *.interkh.com и причина проксирования — привязка ссылок к IP.

**Вывод для Lampa Rescue:** надёжный адаптер Lordfilm, вероятно, потребует серверного компонента или проверенного уже работающего backend. Чисто клиентская реализация в старом WebView рискует упереться в челлендж, CORS и CDN-ссылки. Не добавляем выдуманные эндпоинты и не выдаём URL страницы фильма за поток. Следующий этап — проверить контракт Lampac /lite/lordfilm и совместимость старого клиента, затем выбрать минимальный безопасный способ интеграции.
